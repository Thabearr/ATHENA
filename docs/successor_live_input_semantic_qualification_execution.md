## Why matching local legacy code does not rescue the chain

ATHENA contains older form, Elo, and fatigue implementations. They are not part
of the exact PR66 -> PR31 reviewed lineage.

That distinction matters. A locally present algorithm cannot retroactively prove
that a reviewed FotMob scalar was generated by that algorithm.

There are also legacy behaviors that are unsuitable as automatic proof of exact
historical semantics. For example, the older `TeamFormService` can default form
to `0.50` when history is absent or an error occurs, while the PR78 historical
contract requires missing history to remain missing. The existing database Elo
engine uses mutable persisted team state and date-only historical ordering, while
PR78 freezes a source-scoped deterministic replay with stronger chronology and
ambiguity rules. The fatigue engine has related no-data behavior outside the
reviewed PR66 ancestry.

PR #79 therefore does not infer equivalence from the existence of these modules.
